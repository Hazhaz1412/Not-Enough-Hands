# Toilet Ghost

This folder holds two separate assets for the same character. They are
independent on purpose:

| File | What it is | Used by |
|---|---|---|
| `toilet_ghost_model.glb` + `toilet_ghost_model.tscn` | The 3D model (Sprint 3). Geometry and materials only - no script, no audio, no gameplay. | Nothing yet - see "Not yet wired in" below. |
| `toilet_ghost.tscn` | The gameplay scene (Sprints 1-2): a billboarded `Sprite3D` plus `minigames/toilet_ghost.gd` and the teleport audio. | `minigames/toilet_minigame.tscn` |

## The 3D model (Sprint 3)

`toilet_ghost_model.glb` is generated by `toilet_ghost_model.py`, a seeded
Blender script kept beside it so the model stays reproducible and tweakable
rather than being an opaque binary. Regenerate with:

```
blender --background --python assets/ghosts/toilet_ghost/toilet_ghost_model.py \
        -- assets/ghosts/toilet_ghost/toilet_ghost_model.glb
```

Structure, scale and orientation:

```
ToiletGhostModel (Node3D)          toilet_ghost_model.tscn
└── Model                          instance of toilet_ghost_model.glb
    ├── GhostBody  (MeshInstance3D, 7 materials, opaque)
    └── GhostWisps (MeshInstance3D, 1 material, alpha-blended)
```

- **Scale** ~1.65 m tall, ~0.69 m wide. The face sits at ~1.58 m, just above
  the player's 1.495 m eye height (`player.gd`: `standing_height` 1.75 with the
  capsule centred on the origin, plus a 0.62 camera pivot), so it meets the
  player's gaze slightly from above.
- **Origin** is on the floor at (0,0,0), body above it. The wisps stop ~0.13 m
  short of the floor so the ghost reads as floating; gameplay can therefore
  drop it straight onto a floor position with no corrective offset.
- **Orientation** faces -Z, matching Godot's forward convention. The 180-degree
  correction for Blender's -Y-forward authoring is baked into the exported
  mesh, so the scene needs no fix-up rotation.
- ~10.7k triangles, no rig, no skeleton, no animation, no collision (matching
  `assets/House.glb`, which is also imported as render geometry only).

Materials are eight plain `StandardMaterial3D`s - no custom shaders. Skin,
teeth and eye whites carry a low emission so the face stays readable in an
unlit bathroom without needing a dedicated light.

### Not yet wired in

Sprint 3 was model-only. `toilet_ghost.tscn` still uses the flat `Sprite3D`,
so **the minigame currently shows the sprite, not this model**. Swapping them
is gameplay integration and belongs to a later sprint.

## Source image

Both assets derive from `res://assets/images/anh-ma-kinh-di-20.jpg` (already in
the repository, reused in place) - a pale, unnaturally tilted face with wide
unblinking eyes and a wide, tooth-filled grin, surrounded by near-black
hair/shadow filling most of the frame.

The model does **not** project that photo onto geometry (that would produce
exactly the flat, photographic look the model exists to replace). Instead the
image was sampled for its palette and its features rebuilt as geometry:

- pale skin `rgb(84,87,119)`, highlight `rgb(111,119,155)`, shadow
  `rgb(36,34,51)`, near-black surround `rgb(2,2,6)` (77% of the image) - the
  cold blue-lavender cast is taken straight from these samples;
- the enormous gaping mouth is a real carved cavity with irregular teeth;
- the eyes are oversized and asymmetric, with the whites visible all around a
  small dark iris;
- the head carries a 52-degree roll about the view axis, reproducing the
  reference's sideways tilt while keeping the face toward the player.

**Sprite-only limitation:** unlike `assets/minigame/door_ghost_face_v2.png`,
the source is a JPEG and carries no alpha, so `toilet_ghost.tscn`'s `Sprite3D`
renders as an opaque rectangle. It reads acceptably because the image's own
background is near-black, but there is no true cutout. The 3D model supersedes
this once gameplay adopts it.
